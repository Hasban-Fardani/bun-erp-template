# UI registry and atomic design

1. Read `packages/ui/llms.txt` first: it indexes every module with its layer, purpose, main exports and the sibling it replaces, and its Parallel variants table says when to pick `badge`/`badge-primitives`, `card`/`card-primitives`, `select`/`select-primitives`, `dropdown-menu`/`dropdown-menu-primitives` and `toast`/`toast-primitives`. `bun loom check:ui-guide` fails when a component module is missing from that guide or an entry points at a missing file. Then search `packages/ui/src` and its imports before creating a component; extend an existing atom or molecule when it already owns the behavior. **The library is intentionally broader than current usage**: a component with no importer is a reference pattern that shows the house style, so never delete one as "unused" and never invent a variant when a parallel one already exists. Check whether a shared component already owns the interaction — the list states in `@loom/data-table` (`resource-table.tsx`/`server-table.tsx`), feedback (`toast`, `alert`) and motion (`styles.css` keyframes and reduced-motion guard) — before adding motion or a new variant.
2. Inspect the exact item before implementation. Only the aliases and URLs in `packages/ui/registry-allowlist.json` are installable: `@shadcn`, `@dashboardcn`, `@dashboardblocks`, `@emailcn`, and `@pdfcn`. Do not add registries without an owner decision and gate update.
3. Put reusable presentation in the smallest correct layer: atom, molecule, organism, then template. Application state, RPC, routing and feature rules stay in the consuming app or feature.
4. Record provenance in the catalog beside the source: `packages/ui/component-sources.json`, `dashboard-sources.json`, and `tanstack-sources.json` cover UI; `templates/packages/email-templates/component-sources.json` and `templates/packages/pdf/component-sources.json` pin the opt-in packages' vendored files to an MIT-licensed commit (validated once installed). Custom compositions cite an official reference and explain their behavior.
5. Run `bun loom check:shadcn`, `bun loom check:architecture`, `bun loom check:gate motion` when adding or changing animation, and the relevant UI tests. The registry gate must pass without weakening its allowlist.
