# Internationalization

`@loom/i18n` is the shared localization package for the web and mobile apps. It ships `en-US` and `id-ID`; English is the fallback for unsupported locales and messages missing from a catalog.

Wrap each app root in `I18nProvider` and use `useI18n()` from `@loom/i18n/react` for translated messages and locale-aware number, date, date-time, and relative-time formatting. `LocaleSwitcher` lets users choose a supported locale. The provider detects a saved choice first and then browser or device preferences, and safely continues when browser storage is unavailable.

The core entry point, `@loom/i18n`, contains no React dependency and does not read browser globals during import. This keeps locale resolution and formatting available to server and worker code. React applications should import the provider from the `/react` entry point. Indonesian messages load on demand; the English catalog is the initial fallback.

Message keys, code identifiers, enum values, and API data remain in English. Translate copy owned by the interface, including labels and templates that contain dynamic values. Keep API-provided error text and user-authored content intact. When adding a message, add it to both catalogs; the Indonesian catalog's type check enforces the same key set as English.

Shared UI components do not depend on the i18n package. They provide typed labels with English defaults, and app call sites pass localized labels. This keeps `@loom/ui` independent of React context and lets components remain usable outside the apps.
