## Scope

Add PostgreSQL-backed background execution, independent mobile offline persistence, cross-app
utility and UI registry rules, and project-init setup. Keep the API, web, mobile and shared package
ownership legible. Refresh the active guide so it matches source and gates; archive research as
historical rather than operational instruction.

## Implementation

- Add an at-least-once queue with leased claims, idempotent enqueue, bounded retries, dead-job
  review and Bun/Cloudflare workers.
- Use PostgreSQL through postgres.js in every server runtime and an isolated PostgreSQL database for
  tests; the mobile SQLite store is separate.
- Organize server code under `features`, use small TanStack route wrappers with feature screens,
  lazy route chunks and shared accessible pending states. Page files use no `-page` suffix.
- Add `packages/utils` promotion criteria, feature responsibility folders, atomic UI guidance,
  shadcn registry allowlist and source gate, and one-time CodeGraph/agent-skill initialization.
- Add namespaced mobile local records using encrypted native SQLite and IndexedDB for browser
  development, with logging/versioning skills and Android/iOS build/release workflows.
- Update README, AGENTS, architecture and operations guides to identify current owners and runtime
  boundaries. Preserve historical research with explicit labels.
