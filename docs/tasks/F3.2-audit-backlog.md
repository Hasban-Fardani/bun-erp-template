## P0 — real bugs / security

- [x] **System-role permissions reset on every boot.** `S/bootstrap/server.ts:49` runs `seed()`; `seedRbac`
  (`S/features/rbac/service.ts:63-66`) deletes and re-inserts `role_permissions` for system roles, no transaction.
  Edits to `owner`/`staff` are lost on restart; a second replica booting leaves them empty briefly.
  Fix: insert only missing rows, one transaction.
- [x] **Open self sign-up, unaudited.** `S/features/identity/auth.ts:28-34` has no `disableSignUp`; tests rely on
  `/api/v1/auth/sign-up/email`. With `organizations` installed, anyone can also create organizations.
- [x] **No auth hardening.** No `rateLimit`, no `advanced.ipAddress` headers, no cookie attributes. `TRUST_PROXY`
  (`S/config/schema.ts:44`) is defined but never read.
- [x] **Malformed `:id` returns 500** instead of 404/422 (breaks the 401/403/404 rule). `validate("param")` is never
  used: `identity/route.ts:62,97,115,133,149,164`, `rbac/route.ts:86,101,122`, `notifications/route.ts:85`,
  `F/departments/server/route.ts:62,101`. Fix: shared `idParam` zod schema.
- [x] **Unique-constraint races surface as 500.** `createUser` (`identity/service.ts:178`), `createRole`
  (`rbac/service.ts:145`) are check-then-insert; `assignRole` (`rbac/service.ts:270-278`) is select-then-insert;
  `updateDepartment` (`F/departments/server/service.ts:75`) has no conflict check on `code`. `S/http/error-handler.ts`
  has no mapping for Postgres `23505`. Fix: central `23505` → `ApiError.conflict`, `onConflictDoNothing`.
- [x] **(verify) Dockerfile runtime stage copies only `packages/utils`** (`Dockerfile:20-22`) but the server imports
  `@bun-erp/storage/server` (`S/infra/storage.ts:1`, `S/package.json:14`). The symlink likely dangles at runtime.
  Fix: copy `packages/storage` (or all `packages/`); add CI step that builds the image and hits `/api/v1/health`.
- [x] **Slop gate passes when the validator crashes.** `cli/gates/slop.ts:82-92` returns `[]` on any non-zero exit
  with no line matching `/^[A-Z_]+ /`.
- [x] **QA script fails on a default install.** `templates/apps/web/tests/browser/admin-workflow.ts:75-120` drives
  `/users`, `/roles`, `/audit`, `table-search` (catalog features, not installed by default); one big `try`
  (`:298-301`) aborts everything on first error. It never checks notifications, sign-out, or the unauthenticated
  redirect. Fix: core suite + per-feature suite, per-check isolation (or `@playwright/test`).
- [x] **Dead regex in readiness gate.** `cli/gates/readiness.ts:87-88` builds `.id\b` in a normal string, so `\b`
  is a backspace char and the domain alternative matches nothing (confirmed with `bun -e`).

## P1 — design, resilience, consistency

### Server
- [ ] No privilege-escalation guard: a `role.assign` holder can assign `owner`; a `role.update` holder can grant any
  permission. Nothing prevents removing the last owner (`deleteUser` `:219`, `revokeUserRole` `:273`,
  `replaceUserRoles` `:300`, editing `owner` permissions).
- [ ] Permission cache invalidated before commit (`rbac/service.ts:256,279,287`; only `replaceUserRoles`
  `identity/service.ts:328` invalidates after). Cache is per-process, so CLI `user:revoke` leaves access live up to 30s.
- [ ] `user:passwd` (`S/cli/commands/user.ts:256-297`): `Math.random()` password (`:263`); updates all accounts, not
  only `providerId='credential'` (`:277-280`); does not revoke sessions.
- [ ] Job lease: any renewal error sets `leaseLost` (`S/infra/jobs/queue.ts:137-150`), discarding a successful
  result and re-running the job (duplicate mail etc.). Treat only a zero-row result as lost.
- [ ] Job with no registered handler is dead-lettered on first claim (`queue.ts:119-127`); breaks rolling deploys.
- [ ] Mail not enqueued in the feature transaction (AGENTS.md rule): `F/mail/server/wiring.ts:9-17` binds root `db`,
  `notify` (`S/features/notifications/service.ts:16-21`) takes no tx. `F/mail/server/channel.ts:16-23` has no
  `idempotencyKey`; `mail.send` handler (`wiring.ts:26-28`) casts payload to `MailMessage` unvalidated.
- [ ] Migrations: no advisory lock (`S/database/migrate.ts:12-31`), run on every context creation
  (`S/bootstrap/bootstrap.ts:24`); `migrationId` (`:34`) compares only the 4-digit prefix, so duplicate numbers
  silently skip the second.
- [ ] Notifications validate query before auth (`S/features/notifications/route.ts:44-46`): anonymous + bad query
  gets 422, not 401 (contradicts `S/http/helpers/authorize.ts:6`).
- [ ] `ApiError.conflict` (`S/http/helpers/errors.ts:53-55`) always attaches `{path:"code"}`, wrong for "cannot
  delete yourself" (`identity/service.ts:226`), "role in use" (`rbac/service.ts:207`), duplicate email.
- [ ] N+1: `rbac/route.ts:47-49` (`permissionsForRole` per role), `S/cli/commands/user.ts:106` (`rolesForUser` per user).
- [ ] `/api/docs` and `/api/openapi.json` always public (`S/http/app.ts:18-31`).
- [ ] Organizations schema: no unique `(organization_id, user_id)` on `member`
  (`F/organizations/server/schema.ts:40`); `session.active_organization_id` has no FK/index.
- [ ] `role:create` not atomic (`S/cli/commands/role.ts:79-84`): bad permission key leaves a half-created role.
