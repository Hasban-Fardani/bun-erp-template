# F3.0 — Modular program

## Goal

Make `apps/*` as lean as possible (Laravel-like DX), let `packages/*` hold the bulk and be
installable on demand, make the CLI thin and extensible, and make tests come first.

## Decision log (settled)

| # | Decision |
|---|---|
| Q1 | Default apps = `apps/server` + `apps/web`; mobile moves to a catalog |
| Q2 | Opt-in packages: git source now, npm later |
| Q3 | Core packages = `ui`, `i18n`, `utils`, `storage`; opt-in = `data-table`, `charts`, `editor`, `email`, `pdf` |
| Q4 | `apps/server` uses `features/<name>` (not Laravel's `app/`, which is non-standard in JS) plus `routes/`, `config/`, `database/`, `bootstrap/`, `http/`, `http/kit/`, `infra/` |
| Q5 | CLI lives in root `cli/{index.ts,commands/,tasks/,lib/}` + `gates/` |
| Q6 | `tsc --incremental`; `*.tsbuildinfo` gitignored |
| Q7 | Phased, sequential, `bun erp check` green per phase, report each phase |
| Q8 | Opt-in packages from a git repo now, npm later |
| Q9 | Default web = login + Beranda; users/roles/audit become add-ons; every feature is pluginable |
| Q10 | Hono: full `factory` pattern with typed variables |
| Q11 | Commands auto-discovered from `cli/commands/**` and `packages/*/cli/commands/**` |
| Q12 | Mobile moves to `templates/apps/mobile/`, lean (no stray `node_modules`) |
| Q13 | `apps:create <name> <jenis>` (jenis required); missing required args prompt interactively like artisan |
| Q14 | `i18n` is mandatory (core), internationalization from the start |
| Q15 | Installed features land directly in `apps/*` and auto-wire |
| Q16 | NestJS-lite: `defineFeature(...)` descriptor + `registerFeature()` |
| Q17 | Auto-wire generates the explicit `app.route()` mount so RPC types survive |
| Q18 | Mobile moves to `templates/apps/mobile/` and `apps/mobile` is removed from default; restored via `apps:create <name> mobile` |
| Q19 | `i18n` moves to core (default) |
| Q20 | TDD-first is enforced by a `tdd` gate + AGENTS.md rule: every server feature has a test, generators emit tests, and task evidence shows red→green |
| Q21 | Plan/task files reuse `docs/tasks/*.md` plus `bun erp task:new <id> <title>` |
| Q22 | Route tests use `hono/testing` `testClient(app)` (typed), `app.request` only where needed |
| Q23 | The template repo ships `apps/` empty; CI runs `bun erp init --apps server,web --yes` |
| Q24 | `init` offers every combination (server, web, mobile, server+web, server+mobile, web+mobile, all); backend keeps Hono RPC, web drops RPC when no backend and re-fits when one is added |
| Q25 | `init` is one door: choose apps + agent tooling + first `bun install` |
| Q26 | A package splits `src/<target>` only when it has more than one target; pure UI stays flat; `data-table` becomes `src/ui` + `src/server` |
| Q27 | `organizations` is a plugin; plugin migrations stay forward-only and compatible |
| Q28 | RBAC, organizations, and departments are separate concerns: RBAC installs without org/department, and never drags them in |
| Q29 | Seven app combinations; missing input prompts as an artisan-style **choice list**, not free text |
| Q30 | Web without a backend ships no RPC client/`app-type` dep; adding a server later re-injects them |
| Q31 | Package target dirs: `src/ui` (browser), `src/server`, `src/capacitor` (native), `src/utils` (all sides) |
| Q32 | RBAC foundation is Better Auth `access`/`admin`; a thin optional `rbac` plugin adds app permission statements |
| Q33 | `organizations` uses the Better Auth `organization` plugin; default server has no tenant; org columns belong to that plugin |
